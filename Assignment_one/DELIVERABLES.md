## 📋 Architecture Summary

### Sender Pipeline (Client)
```
Application Record
    ↓ (plaintext)
Record Processing
    ↓
Nonce Generation (unique)
    ↓
Associated Data (AAD)
    ↓
AEAD Encryption (AES-GCM or ChaCha20)
    ↓
Protected Record (serialized JSON)
```

### Receiver Pipeline (Server)
```
Protected Record (JSON)
    ↓
Replay Verification (sequence check)
    ↓
Authentication Verification (tag validation)
    ↓
Decryption (plaintext recovery)
    ↓
Application Record (if all checks pass)
```

## 🔑 Key Design Features

### 1. Unified AEAD Engine
- Single interface for both algorithms
- Automatic tag extraction
- AAD support

### 2. Counter-Based Nonce Generation
- 4-byte random prefix + 8-byte counter
- Guarantees 2^64 unique nonces per key
- No collision risk

### 3. Sliding Window Replay Detection
- Efficient memory usage
- Window size: 10,000 records (configurable)
- Detects duplicate and out-of-order records

### 4. Strict Failure Handling
- Never releases plaintext if authentication fails
- Detailed error messages
- Comprehensive logging

### 5. JSON-Based Record Format
- Human-readable
- Easy to parse and serialize
- Includes algorithm selection
